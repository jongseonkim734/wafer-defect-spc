# wafer-defect-spc
> 반도체 웨이퍼 불량 데이터를 통계적 공정관리(SPC) 와 머신러닝 두 축으로 분석하는 프로젝트
> 메모리 반도체 전공정의 수율 및 품질 업무에서 요구하는 공정 이해, 불량 분석, 유효 인자 감지, 통계적 공정관리, 수율 개선을 실제 데이터로 구현 및 증명하는 것이 목표

> 실제로 한 일을 6시그마 DMAIC에 매핑해 어느 단계가 비어 있는지 확인했다. 단계별 충족도와 남은 빈칸은 [`docs/dmaic.md`](docs/dmaic.md).

## 핵심 결과

> 프로젝트 구조: 하나의 목표, 두 층위. "불량을 놓치지 않아 수율을 지킨다"는 목표를 전공정의 두 지점에서 공략
> 공정 중 센서 데이터(SECOM)로 불량을 예측하고 유효 인자를 선별(원인 층), 공정 후 웨이퍼 불량맵(WM-811K)을 CNN으로 분류 및 해석(결과 층)
> 두 층 모두 클래스 불균형에서 소수 불량의 recall을 우선하는 같은 규정을 따른다.

### ① 유효 인자 선별로 재현율 개선 (SECOM, 로지스틱 회귀)

| 모델 | 피처 수 | fail F1 | fail recall | 비고 |
|---|---|---|---|---|
| baseline | 590 | 0.14 | 0.19 | 불량 4/21 검출, 590피처 vs 1,253샘플 → 과적합 |
| SelectKBest k=30 | 30 | 0.28 | 0.71 | ANOVA F-검정 |
| SelectKBest k=10 | 10 | 0.33 | 0.76 | 불량 16/21 검출 (k-sweep best) |

- recall 0.19 -> 0.76: 품질에서 가장 중요한 재현율이 크게 개선
- 낮은 precision이라는 단점 존재
- 단, 반도체 품질은 False Negative가 False Positive보다 치명적이라 recall이 우선.

![k-sweep: 피처 수(k) vs fail F1/recall](docs/figures/secom_feature_k_sweep.png)

### ② SPC 관리도(X-bar / R) 구현 및 이탈점 검출

![X-bar chart & R chart](docs/figures/xbar_and_r_chart.png)

> 유의: SECOM은 단일 공정의 균일 시계열이 아니라 subgroup을 임의(연속 5개)로 잘랐고, 관리한계선을 같은 데이터로 산출(Phase 1). 이 관리도는 SPC 방법론 시연이지 해당 센서 공정의 품질 판정이 아니다. (자세한 근거는 `docs/devlog.md`)

#### ②-2 공정 이상의 원인 인자 자동 진단 — 예측에서 진단으로

이 Lot이 불량인가를 아는 것만으로는 현장에서 조치할 수 없다. 필요한 건 어느 인자를 먼저 점검하라 이다.
정상(pass) Lot으로만 센서별 기준선을 세우고, 각 Lot이 기준선에서 몇 σ 벗어났는지로 원인 인자를 순위화했다.

![SECOM 원인 인자 진단 (Lot 2 / 10 / 14)](docs/figures/secom_fdc_diagnosis.png)

- 감시 대상 선별의 안정성: ①과 동일한 기준(ANOVA F-검정, k=10)으로 감시 인자를 선별했고, train 80%로 뽑은 ①의 결과와 전체 데이터로 뽑은 결과가 10개 중 7개 일치했다 → 표본이 달라져도 유효 인자가 안정적으로 유지됨.
- 원인 인자가 그룹으로 움직인다: Lot 10·14에서 인접 번호 센서 430·431·434·435가 동반 이탈(6σ, 12~13σ). Lot 14에서는 네 센서가 모두 정확히 400.000으로 포화되어, 네 개의 독립 문제가 아니라 하나의 근본 원인이 네 인자에 동시 반영되었음을 시사한다. 단 400.000이 센서의 측정 상한인지 데이터 기록 과정에서 잘린 값인지는 확인할 수 없다.
- 불량마다 원인이 다르다: 반면 Lot 2는 510번 단독 5.2σ로 완전히 다른 패턴 → 진단이 실제로 변별력을 갖는다는 근거.
- 한계: SECOM 센서는 익명화되어 물리적 의미를 알 수 없어 원인 공정을 특정할 수는 없다. 원인 인자 후보를 좁히는 방법론 시연이며, 실제 팹에서는 이 인자가 장비·파라미터에 매핑되어 공정 추적으로 이어진다.
- 탐지 규칙 자체(3σ 단독)는 fail 19.2% 탐지 / pass 5.5% 헛경보(lift 3.5배)로, 단일 시점 임계값의 한계도 함께 확인했다. (`docs/devlog.md` 08/25)

### ③ WM-811K 웨이퍼 불량 8종 CNN 분류

25,519장의 웨이퍼 불량 맵을 64×64로 리사이즈해 CNN 모델로 8종 분류. 불균형(Edge-Ring 9,680장, Near-full 149장)을 보정하기 위해 class_weight="balanced"를 활용.

> 불균형 데이터라 accuracy는 다수 클래스 착시가 있어, **macro F1을 주지표**로 두고 per-class로 정직하게 평가한다.

| 지표 | 값 |
|---|---|
| macro F1 | 0.842 |
| 소수 클래스(Near-full, 30장) | recall 0.97 |
| 최약 클래스(Scratch) | recall 0.57 · F1 0.568 |

- 불균형 보정 검증: 표본 30장 뿐인 Near-full까지 recall 0.97로 검출 → class_weight가 소수 클래스를 잘 보정했음을 per-class로 확인.
- 오류의 물리적 해석: Scratch의 약 33%가 Loc로 오분류. Scratch와 Loc이 공간적으로 유사한 패턴이라 모델의 혼동이 도메인적으로 납득 가능.

![WM-811K CNN confusion matrix (행 정규화)](docs/figures/wafer_cnn_confusion.png)

- Grad-CAM으로 오류 근거 검증: Scratch→Loc 오분류 사례의 히트맵이 노이즈가 아니라 실제 스크래치 궤적에 집중 → 모델은 결함 위치를 옳게 짚되, 선형 궤적을 국소 덩어리(Loc)로 해석. 오류의 원인이 오작동이 아니라 형태적 경계 모호성임을 시각적으로 확인.

![WM-811K CNN Grad-CAM (Scratch→Loc 오분류)](docs/figures/wafer_cnn_gradcam.png)

불량 패턴 → 전공정 공정 원인 (불량 분류를 공정 개선으로 잇는 다리)

웨이퍼 불량맵은 EDS(전공정의 마지막 관문)에서 나온 전공정 수율 결과물이다. 따라서 불량 패턴 분류는 그 자체가 목적이 아니라, 어느 전공정 단계를 개선해야 하는지 진단하는 출발점이다. 각 패턴은 대표적으로 다음 공정을 가리킨다(실제 근본원인은 FA로 확정).

| 패턴 | 대표 공정 원인 | 관련 전공정 |
|---|---|---|
| Center | 증착/CMP 중심부 불균일, 스핀코팅 | ThinFilm · CMP · Photo |
| Donut | 반경방향(radial) 불균일 | CMP · ThinFilm |
| Edge-Ring | 가장자리 식각/증착 불균일, edge exclusion | Etch · ThinFilm |
| Edge-Loc | 가장자리 국소 이상(척 접촉·핸들링) | Etch · 장비 Set-up |
| Loc | 국소 오염·파티클 | Cleaning · 파티클 관리 |
| Near-full | 대형 공정 이탈(레시피·장비 이상) | 공정 안정화 · 장비 Set-up |
| Random | 무작위 파티클 오염(환경·자재) | Cleaning · 환경 |
| Scratch | 기계적 핸들링 손상, CMP 스크래치 | CMP · 핸들링(장비 Set-up) |

→ 8개 패턴이 모두 전공정 단위공정(Photo/Etch/ThinFilm/Cleaning&CMP + 장비 Set-up)으로 추적된다. 불량 분석 → 공정 원인 진단 → 조건 최적화로 이어지는 수율 개선 고리의 앞단.

### ④ Scratch 개선 실험 3종 실패 → 원인은 데이터가 아니라 내 전처리 결정이었다

Grad-CAM 진단을 바탕으로 세 가지 처방을 동일 조건 A/B로 검증했으나, 모두 baseline을 넘지 못했다.

| 실험 | 가설 | 결과 |
|---|---|---|
| 회전/반전 증강 | 방향 불변성 학습으로 Scratch 다양성 확보 | Scratch→Loc은 줄었으나 Loc→Scratch가 폭증, 전 클래스 F1 하락(순손실) |
| 해상도↑ (64→96) | 가는 선 형태를 더 보존 | macro 0.842→0.807, Scratch F1 0.568→0.457 (64 완승) |
| 고전 도메인 피처 | 스크래치는 물리적으로 '선' → 직선성·종횡비로 분리 | Scratch/Loc 분포가 겹쳐 분리 실패 (중앙값 1.17 vs 1.17) |

세 실패의 공통점을 다시 보니 전부 64×64 축소본 위에서 이뤄진 처방이었다. 그래서 리사이즈하지 않은 원본 웨이퍼맵으로 돌아가, 결함 픽셀을 연결요소로 분리한 뒤 가장 긴 성분의 종횡비를 측정했다.

![원본 해상도에서의 Scratch vs Loc 분리력](docs/figures/wafer_shape_original_res.png)

| | 64×64 (전체 픽셀) | 원본 해상도 (연결요소 분리) |
|---|---|---|
| Scratch 종횡비(중앙값) | 1.17 | 5.78 |
| Loc 종횡비(중앙값) | 1.17 | 1.86 |
| 사분위 범위 | 완전히 겹침 | 완전히 분리 (Loc 75% 2.53 < Scratch 25% 4.07) |

- 종횡비 단일 임계값(> 4.0)만으로 Scratch F1 0.777. 학습된 CNN이 64×64에서 낸 0.568보다 높다.
  *(단서: 8클래스 vs 2클래스라 직접 비교는 아니며, 임계값을 같은 데이터에서 골라 낙관적 추정이다.)*
- 결론이 뒤집혔다: Scratch↔Loc 혼동은 데이터의 근본적 한계가 아니라, 파이프라인 맨 앞의 64×64 리사이즈 결정이 형태 정보를 파괴한 결과였다. 지워진 정보는 그 위에서 무엇을 해도 되살아나지 않으므로, 앞선 세 처방은 실패할 수밖에 없었다. 96×96으로는 부족했다. 여전히 많은 정보가 지워져있었다.
- 배운 것: 모델을 의심하기 전에, 파이프라인의 가장 앞단에서 **무엇을 버렸는지** 먼저 확인해야 한다.
- 부수 수확: 큰 모델에서 val_loss·val_accuracy가 어긋나 EarlyStopping이 undertrain된 모델을 복원하는 현상을 발견하고, monitor를 분류 품질(val_accuracy)에 맞게 교정. (상세: `docs/devlog.md` 08/22~08/25)
- 64x64에서 발생한 형태적 모호성이 원본 해상도에서는 사라졌음을 알 수 있다.

## 분석 단계 (DMAIC 매핑)

> 이 프로젝트는 6시그마를 배우기 전에 시작했다. 결과적으로 DMAIC와 상당 부분 겹치지만 **방법론을 의식하고 설계한 것은 아니었다.**
> 아래 표는 *실제로 한 일*을 6시그마 DMAIC와 전공정 엔지니어 직무의 요구 역량에 **양쪽으로 나란히** 매핑한 것이다.
> ⬜은 아직 하지 않은 것으로, 있는 척하지 않고 그대로 둔다. 단계별 충족도와 채울 계획은 [`docs/dmaic.md`](docs/dmaic.md).

| DMAIC | 실제로 한 일 | 대응하는 직무 역량 | 상태 |
|---|---|---|---|
| **Define** | 대상 선정(SECOM 공정중 센서 / WM-811K 공정후 불량맵), 성공 기준을 **recall 우선**으로 정의 | 불량 분석 방향 설정 | ✅ 부분 |
| **Define** | CTQ 명문화 · SIPOC · 목표수준 근거 | 과제 정의 | ⬜ |
| **Measure** | 데이터 적재·구조 파악(`01_eda.py`), 결측(median)·불균형(class_weight) 처리 | 데이터 분석 역량 | ✅ |
| **Measure** | 관리도(X-bar/R)·공정능력 Cp/Cpk 직접 구현 + 단위 테스트(`src/spc.py`, `tests/`) | **통계적 공정관리(SPC)** | ✅ |
| **Measure** | MSA — 분류기의 반복성·재현성, Kappa 일치도 | 계측 신뢰성 | ⬜ |
| **Analyze** | ANOVA F-검정으로 590개 → 유효 인자 10개 선별(k-sweep) | **유효 인자 감지** | ✅ |
| **Analyze** | 정상 Lot 기준선 대비 z-score로 **원인 인자 순위화**(`05_secom_fdc.py`) | 불량 원인 추적 | ✅ |
| **Analyze** | Grad-CAM으로 오분류 판단 근거 시각화 | 불량 분석 | ✅ |
| **Analyze** | 특성요인도(5M1E) + FMEA로 원인 구조화 | 근본원인 도출 | ⬜ |
| **Improve** | CNN 8종 분류(macro F1 0.842) + baseline 로지스틱 회귀 개선(recall 0.19→0.76) | **AI 기법 활용 불량 예측** | ✅ |
| **Improve** | 개선 실험 A/B 3종 → 실패 → **원본 해상도 형태 피처로 결론 반전** | 조건 최적화 | ✅ |
| **Improve** | DOE 2³ 요인배치로 실험 재설계(교호작용 확인) | 실험 설계 | ⬜ |
| **Control** | 관리계획서 + 모델 성능 관리도(배치별 macro F1 관리한계선) | **수율 개선 / 품질 관리** | ⬜ |
| **Control** | 회고·의사결정 기록(`docs/devlog.md`) | — | ✅ |

**남은 작업 (위 ⬜ 외)**
- 이상탐지(Isolation Forest / Autoencoder)
- 결과 시각화·대시보드
