# wafer-defect-spc

반도체 웨이퍼 불량 데이터를 **통계적 공정관리(SPC)** 와 **머신러닝** 두 축으로 분석하는 프로젝트.
삼성전자 DS 평가및분석 직무에서 요구하는 "불량 분석 · 유효 인자 감지 · 통계적 품질관리 · 수율 개선"을
실제 데이터로 구현·증명하는 것을 목표로 한다.

> **분석 문서 구조는 6시그마의 DMAIC 프레임을 따른다.** (자격증 대신 방법론을 프로젝트로 체화)

---

## DMAIC 진행 로그

### D — Define (문제 정의)
- [ ] 무엇을 풀 것인가: (예) 웨이퍼맵 불량 패턴을 자동 분류하고, 공정 파라미터의 이상을 통계적으로 탐지한다.
- [ ] 성공 기준: (예) 분류 F1 ≥ 0.__, 관리도로 이상 로트 검출.
- [ ] 왜 중요한가: 수율/품질 직결. (본인 언어로 채우기)

### M — Measure (측정)
- [ ] 데이터셋 확보 및 적재 → `data/README.md` 참고
- [ ] 기초 통계·결측·클래스 불균형 파악 (`notebooks/01_eda.py`)

### A — Analyze (분석)
- [ ] SPC: 관리도(X-bar/R), 공정능력지수 Cp/Cpk (`src/spc.py`)
- [ ] 불량 패턴 분포·상관, 유효 인자(feature) 선별

### I — Improve (개선)
- [ ] ML 분류(baseline → CNN), 이상탐지
- [ ] SPC + ML 통합 파이프라인

### C — Control (관리)
- [ ] 결과 시각화/대시보드, 재현 가능하게 정리
- [ ] 회고 및 한계 (`docs/devlog.md`)

## 폴더 구조
```
wafer-defect-spc/
├── README.md            # 이 파일 — DMAIC 진행 상황
├── requirements.txt     # 파이썬 패키지
├── .gitignore
├── data/                # 데이터셋 (원본은 git에 올리지 않음)
│   └── README.md        # 다운로드 방법
├── notebooks/           # 탐색·실험 (# %% 셀 단위 실행 가능)

├── src/                 # 재사용 로직

    └── devlog.md        # 개발일지 — "왜 이렇게 했는지" 기록 (신뢰도의 증거)
```

## 신뢰도 원칙 (중요)
- **매일 조금씩 커밋** — 한 번에 몰아 올리지 않는다. 잔디가 곧 "직접 했다"는 증거.
- **devlog.md에 실패·의사결정 기록** — 사람이 한 흔적을 남긴다.
- **모든 코드는 내가 설명할 수 있어야 한다** — 면접 최종 방어선.
